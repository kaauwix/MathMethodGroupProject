# MathMethodGroupProject

# Документация проекта

## 1. Общая информация

Проект предназначен для решения задач линейного программирования различными методами.

В проект входят следующие файлы:

- `MethodSelection.py` — центральный диспетчер, который подготавливает задачу и автоматически выбирает подходящий метод решения.
- `PrimalSimplex.py` — реализация прямого симплекс-метода.
- `DualSimplex.py` — реализация двойственного симплекс-метода.
- `MIB.py` — реализация метода искусственного базиса.
- `AuxiliaryFun.py` — общие вспомогательные функции, используемые алгоритмами.
- `optimal.py` — проверка оптимальности решения.
- `test_run.py` — тестирование методов и проверка результатов.

## 2. Общая схема работы программы

Для решения задачи используется одна публичная функция:

`solve_problem(c, A, b, signs, objective="max", max_iterations=1000)`

Она находится в `MethodSelection.py`.

Функция принимает:
- `c` — коэффициенты целевой функции;
- `A` — матрицу коэффициентов ограничений;
- `b` — вектор правых частей;
- `signs` — знаки ограничений (`<=`, `>=`, `=`);
- `objective` — направление оптимизации (`max` или `min`);
- `max_iterations` — максимальное количество итераций.

После получения исходных данных диспетчер:

1. Приводит задачу к канонической форме с помощью `normalize_problem()`.
2. Строит начальную симплекс-таблицу.
3. Проверяет наличие начального единичного базиса.
4. Определяет допустимость начального плана и выбирает подходящий метод.
5. Передаёт подготовленную задачу соответствующему алгоритму.
6. Возвращает результат решения в едином формате.

Таким образом, пользователю программы не нужно самостоятельно выбирать метод или выполнять предварительную нормализацию задачи.

## 3. MethodSelection.py

Файл отвечает за автоматический выбор метода решения.

Основная функция:

`solve_problem()`

В зависимости от начального состояния задачи выбирается один из алгоритмов:

- `primal_simplex_prepared()` — если начальный план допустим для прямого симплекс-метода;
- `dual_simplex_prepared()` — если выполнено условие двойственной допустимости;
- `artificial_basis_prepared()` — если отсутствует начальный единичный базис.

Если начальное состояние не соответствует условиям поддерживаемых алгоритмов, функция возвращает статус `method_not_applicable` и соответствующее сообщение.

Нормализация выполняется только один раз — в диспетчере. Подготовленная задача передаётся алгоритмам без повторной обработки.

## 4. PrimalSimplex.py

Файл содержит реализацию прямого симплекс-метода.

Основная внутренняя функция:

`primal_simplex_prepared(problem, tableau, basis, max_iterations=1000)`

Алгоритм выполняет следующие действия:

1. Рассчитывает оценки Δj.
2. Проверяет условие оптимальности.
3. Выбирает разрешающий столбец.
4. Определяет разрешающую строку по правилу минимального отношения.
5. Выполняет пересчёт симплекс-таблицы.
6. Обновляет базис.
7. Повторяет итерации до получения оптимального решения или другого условия завершения.

Функция принимает уже нормализованную задачу, начальную симплекс-таблицу и базис.

## 5. DualSimplex.py

Файл содержит реализацию двойственного симплекс-метода.

Основная внутренняя функция:

`dual_simplex_prepared(problem, tableau, basis, max_iterations=1000)`

Алгоритм используется, когда начальный план не является допустимым по правым частям, но выполняется условие двойственной допустимости.

Основные этапы:

1. Проверка правых частей симплекс-таблицы.
2. Выбор разрешающей строки.
3. Выбор разрешающего столбца.
4. Пересчёт симплекс-таблицы.
5. Обновление базиса.
6. Повторение итераций до получения допустимого оптимального решения или другого условия завершения.

Как и прямой симплекс-метод, функция работает с уже подготовленной задачей.

## 6. MIB.py

Файл содержит реализацию метода искусственного базиса (MIB).

Основная внутренняя функция:

`artificial_basis_prepared(problem, max_iterations=1000)`

Метод применяется, если в начальной таблице отсутствует единичный базис.

Основные этапы:

1. Добавление искусственных переменных.
2. Формирование вспомогательной целевой функции.
3. Решение первой фазы симплекс-методом.
4. Проверка возможности получения допустимого базиса.
5. Удаление искусственных переменных.
6. Переход ко второй фазе для оптимизации исходной целевой функции.

Если метод не может получить допустимый базис, возвращается соответствующий статус завершения.

## 7. AuxiliaryFun.py

Файл содержит общие вспомогательные функции, которые используются несколькими алгоритмами.

Основные функции:

- `normalize_problem()` — приведение исходной задачи к канонической форме.
- `build_tableau()` — построение симплекс-таблицы.
- `find_initial_basis()` — поиск начального единичного базиса.
- `calculate_deltas()` — расчёт оценок Δj.
- `pivot_operation()` — пересчёт симплекс-таблицы.
- `recover_solution()` — восстановление значений исходных переменных.
- `determine_method()` — определение допустимости начального плана и подходящего метода.
- `add_text_step()` — добавление текстового этапа решения.
- `add_table_step()` — добавление симплекс-таблицы в историю решения.
- `make_result()` — формирование результата в едином формате.

Также в файле задаётся `EPSILON` — точность сравнения чисел с плавающей точкой.

## 8. optimal.py

Файл предназначен для проверки оптимальности полученного решения.

Содержит функцию:

`check_optimality()`

Она используется для дополнительной проверки результата решения задачи линейного программирования.

## 9. Формат результата

Все алгоритмы возвращают результат с помощью `make_result()`.

Результат содержит:

- `status` — статус завершения;
- `message` — описание результата;
- `steps` — последовательность этапов решения;
- `solution` — найденные значения переменных;
- `objective_value` — значение целевой функции;
- дополнительные данные, например симплекс-таблицу и базис, если они передаются при формировании результата.

Возможные статусы зависят от этапа и причины завершения. Например:

- `optimal` — найдено оптимальное решение;
- `unbounded` — целевая функция не ограничена;
- `infeasible` — задача не имеет допустимого решения;
- `iteration_limit` — достигнуто ограничение по количеству итераций;
- `method_not_applicable` — для начального состояния не реализован автоматический выбор метода.

## 10. Тестирование

Для проверки работы программы используется файл `test_run.py`.

В нём задачи передаются через единую функцию:

`solve_problem()`

Пример вызова:

```python
from MethodSelection import solve_problem

result = solve_problem(
    c=[3, 2],
    A=[[1, 1], [2, 1]],
    b=[4, 5],
    signs=["<=", "<="],
    objective="max"
)

print("Статус:", result["status"])
print("Сообщение:", result["message"])
print("Решение:", result.get("solution"))
print("Значение целевой функции:", result.get("objective_value"))
```

## 11. Архитектурный принцип проекта

В проекте используется централизованная схема управления решением задачи:

- `MethodSelection.py` отвечает за подготовку задачи и выбор алгоритма.
- Файлы отдельных методов содержат только реализацию соответствующих алгоритмов.
- `AuxiliaryFun.py` предоставляет общие функции.
- Все алгоритмы используют единый формат результата.

Исходная задача нормализуется один раз. Отдельные алгоритмы получают подготовленные данные и не выполняют повторную нормализацию.

**Единственная публичная точка входа для решения исходной задачи — `solve_problem()` из `MethodSelection.py`.**
